# Прогнозирование осложнений при бурении

Прогноз риска осложнений (поглощения, ГНВП, прихваты, осыпи и обвалы) для каждого интервала глубины скважины по открытым суточным рапортам бурения месторождения Volve (Equinor).

> **Статус:** предварительное исследование завершено (v0.1). Готовы пайплайн данных, разметка, построение признаков, оценка, пять моделей, ансамбль и однократная проверка на отложенных скважинах. Дальнейшие шаги — в плане работ.

## Предыстория

Проект продолжает мою магистерскую диссертацию (Санкт-Петербургский горный университет, 2019) «Разработка алгоритма расчёта вероятности возникновения осложнений в процессе бурения скважин». Исходный метод оценивал риск осложнений ещё на этапе проектирования скважины по геологическим параметрам и параметрам бурового раствора: перемножались вероятности по каждому параметру, посчитанные по 70+ проектам строительства скважин на месторождениях России. Работа победила на III Международной научно-практической конференции «Бурение скважин в осложнённых условиях» (2018), получила грант УМНИК (2020) и зарегистрирована как программа для ЭВМ (RU 2020614466).

Исходные промысловые данные утеряны, а у метода были известные ограничения: параметры считались независимыми, и оценивалась P(параметр | осложнение), а не P(осложнение | параметры), потому что метод строился только на случаях с осложнениями. В этом проекте подход пересобран на открытых данных в корректной ML-постановке: с отрицательными примерами, валидацией с группировкой по скважинам и явным контролем утечки. Эвристика 2019 года сохранена как бейзлайн.

## Данные

**Источник:** [суточные рапорты бурения Volve](https://huggingface.co/datasets/bengsoon/volve_daily_drilling_report) — разобранная версия суточных рапортов WITSML из открытого датасета Volve: 1 759 рапортов, 26 стволов, 11 скважин.

**Лицензия и указание владельцев:** данные распространяются по Equinor Open Data Licence. Владельцы данных — Equinor и бывшие партнёры по лицензии Volve. Данные не входят в репозиторий; их загружает скрипт `scripts/download_data.py`.

## Пайплайн

```
DataBuilder -> Labeler -> FeatureBuilder -> модели -> ModelSelector (ансамбль с усреднением рангов) -> HoldoutTester
                                              ↑ Evaluator (общий инструмент оценки)
```

### 1. DataBuilder
Разворачивает вложенные записи WITSML в таблицы (`reports`, `status`, `activity`, `fluid`, `lithology`, `pore_pressure`, `survey`), удаляет дублирующиеся версии рапортов, приводит типы и превращает коды пропуска WITSML (`-999.99`, `-999.25`) в пропуски.

### 2. Labeler
Размечает осложнения по журналу операций сразу для всех четырёх типов (мультиметочно):
- **Поиск:** коды операций (например, `interruption -- lost circulation`) плюс правила на регулярных выражениях по текстовым комментариям: *сильные* шаблоны (однозначные формулировки) и *слабые* (кандидаты для планируемой проверки с помощью LLM). Отрицания и посторонний контекст исключаются на уровне фраз («no losses», «losses over shakers», «kick drill», застрявшее оборудование вместо прихвата колонны).
- **Проверка кодов:** там, где коды оказались ненадёжными (например, код управления скважиной использовался для ожидания погоды), код засчитывается только при подтверждении текстом.
- **События:** последовательные операции одного типа в одном стволе объединяются в одно событие. Глубина события — глубина забоя на момент начала события, а не глубина долота: поглощение обычно замечают при СПО или промывке, далеко выше зоны поглощения.
- **Интервалы:** каждый ствол делится на интервалы по 10 м. Интервал считается положительным, если в нём есть событие или он находится сразу над ним. Интервалы ниже глубины события не размечаются: в момент начала события их ещё не существовало.

| Осложнение | Событий в пробуренном диапазоне | Положительных интервалов | Доля |
|---|---|---|---|
| Поглощения | 47 | 69 | 1,0% |
| ГНВП | ниже порога обучения | — | — |
| Прихваты | 44 | 95* | 1,3%* |
| Осыпи и обвалы | 110 | 218* | 3,0%* |

\* до введения несимметричного допуска по глубине; будет обновлено. Событий ГНВП в Volve слишком мало для обучения модели, и пайплайн отказывается обучаться ниже порога, заданного в конфиге.

### 3. FeatureBuilder
Строит признаки для каждого интервала:

| Признак | Источник |
|---|---|
| вертикальная глубина, зенитный угол, его изменение | инклинометрия (интерполяция) |
| диаметр ствола, длина открытого ствола, FIT/LOT | состояние скважины |
| плотность раствора, пластическая вязкость, ДНС | замеры раствора |
| поровое давление (в эквиваленте плотности) | оценки порового давления |
| группа пород, доля глинистых пород | описания литологии (сведены к 10 группам) |
| запас до гидроразрыва = FIT − плотность раствора | производный |
| репрессия = плотность раствора − поровое давление | производный |

Физически невозможные значения превращаются в пропуски по допустимым диапазонам из конфига; длина открытого ствола для боковых стволов отсчитывается от точки зарезки.

### 4. Оценка
- **Валидация с группировкой по скважинам:** боковые стволы одной скважины проходят общую верхнюю часть разреза, поэтому все разбиения делаются по скважинам, а не по стволам.
- **Отложенный тест:** 3 скважины из 11, подобранные так, чтобы и доля интервалов, и доля положительных примеров были близки к 20%.
- **Кросс-валидация:** `StratifiedGroupKFold` по скважинам внутри обучающей выборки; фолды строятся так, чтобы в каждом валидационном фолде были положительные примеры.
- **Метрики:** основная — PR-AUC по объединённым out-of-fold предсказаниям (устойчива к доле положительного класса около 1%); дополнительно — ROC-AUC, Brier score (в сравнении с константным предсказанием доли класса) и F1 при пороге, подобранном по out-of-fold предсказаниям. Метрики на тесте будут с доверительными интервалами бутстрэпом.

## Контроль утечки

Первая версия пайплайна брала признаки интервала из последнего замера до момента, когда долото *вышло* из интервала. Отдельная диагностика (`scripts/diagnose_labels.py`) показала, что так в признаки попадала реакция буровиков на осложнение:

| | До исправления | После исправления |
|---|---|---|
| Положительные интервалы с признаками раствора, замеренными после начала поглощения | **53%** | **4%** |

Исправили двумя изменениями: признаки теперь берутся на момент **входа** долота в интервал (прогноз должен быть доступен до бурения интервала), а интервалы ниже глубины события больше не размечаются.

Утечка заметно влияла на модель: до исправления логистическая регрессия давала запасу до гидроразрыва **положительный** коэффициент (больше запас → выше риск), что противоречит физике поглощений. После исправления знак стал отрицательным.

## Результаты кросс-валидации (поглощения, 8 обучающих скважин)

Все модели оцениваются на одних и тех же 5 фолдах.

| Модель | OOF PR-AUC | Медиана PR-AUC по фолдам | OOF ROC-AUC | OOF F1 |
|---|---|---|---|---|
| Случайная | 0,010 | 0,010 | 0,50 | — |
| Бейзлайн: эвристика диссертации 2019 года | 0,034 | 0,044 | 0,713 | 0,115 |
| Логистическая регрессия | 0,018 | 0,035 | 0,731 | 0,043 |
| Случайный лес | 0,047 | 0,115 | 0,735 | 0,155 |
| LightGBM | **0,056** | 0,090 | 0,720 | **0,175** |
| CatBoost | 0,055 | 0,070 | 0,735 | 0,152 |
| **Ансамбль (случайный лес + LightGBM + CatBoost)** | 0,049 | **0,119** | **0,745** | 0,163 |

**Итоговая модель — ансамбль с усреднением рангов** из моделей, обошедших бейзлайн. Оценка каждой модели переводится в процентиль относительно её собственных out-of-fold оценок, и процентили усредняются: так модели с разной шкалой вероятностей (лес с весами классов и бустинги) вносят равный вклад. На этом шаге ничего не подбирается по данным, а ансамбль оценивается на тех же out-of-fold предсказаниях без переобучения.

**Наблюдения на текущий момент:**
- Все три модели на деревьях обходят эвристику 2019 года, а логистическая регрессия — нет. Деревья делят признаки по порогам и учитывают их взаимодействия (например, высокая репрессия *и* длинный открытый ствол), чего не умеют ни независимые группы эвристики, ни прямые линии логистической регрессии.
- Единственной лучшей модели среди деревьев нет: CatBoost выигрывает два фолда, случайный лес — два других; лес лучше ранжирует интервалы *внутри* скважины, а LightGBM даёт более сопоставимые уровни риска *между* скважинами. Ансамбль объединяет эти сильные стороны: у него лучшие медиана PR-AUC по фолдам и ROC-AUC и второй F1. PR-AUC по объединённым предсказаниям у него чуть ниже, чем у LightGBM и CatBoost — усреднение рангов сжимает верх шкалы, и на самый верх интервал попадает, только если согласны все модели, — но разница меньше разброса между фолдами.
- Веса классов важны: без них ROC-AUC случайного леса немного растёт, но PR-AUC падает на треть. Модель, которая даёт много ложных тревог, для буровика бесполезна, поэтому точность верха списка (PR-AUC) важнее общего упорядочивания (ROC-AUC).
- Три разных алгоритма на деревьях сходятся в самых важных признаках: длина открытого ствола, вертикальная глубина, зенитный угол, поровое давление и запас до гидроразрыва. Вертикальная глубина, вероятно, частично заменяет стратиграфию: свиты на одном месторождении залегают примерно на одних глубинах.
- Логистическая регрессия без флагов пропусков даёт коэффициенты со знаками, ожидаемыми из теории бурения (длинный открытый ствол, высокие плотность раствора, ДНС и репрессия повышают риск; высокие поровое давление, FIT и запас до гидроразрыва снижают его), но у неё мала предсказательная сила; флаги пропусков несут реальную информацию (например, FIT ещё нет в начале секции).
- Одна валидационная скважина стабильно трудна для всех моделей (ROC-AUC 0,41–0,55): поглощения там происходили в условиях, не похожих на остальные скважины.

## Отложенный тест (поглощения, 3 скважины, не участвовавшие ни в обучении, ни в выборе моделей)

Оценка выполнена один раз, после того как все решения по моделям были зафиксированы. Пороговые метрики — при пороге каждой модели из кросс-валидации; 95% доверительные интервалы — бутстрэп по интервалам (несколько оптимистичный, поскольку соседние интервалы одной скважины зависимы).

| Модель | PR-AUC [95% ДИ] | ROC-AUC [95% ДИ] | Precision | Recall |
|---|---|---|---|---|
| Случайная | 0,009 | 0,50 | — | — |
| Бейзлайн: эвристика диссертации 2019 года | 0,022 [0,010; 0,056] | 0,671 [0,551; 0,791] | 0,021 | 0,071 |
| **Ансамбль (итоговая модель)** | **0,048** [0,023; 0,111] | **0,879** [0,836; 0,922] | 0,047 | 0,357 |
| LightGBM | 0,097 [0,029; 0,288] | 0,889 [0,837; 0,936] | 0,045 | 0,429 |
| Логистическая регрессия | 0,071 [0,021; 0,232] | 0,833 [0,732; 0,921] | 0,022 | 0,857 |
| Случайный лес | 0,065 [0,030; 0,147] | 0,895 [0,839; 0,941] | 0,070 | 0,214 |
| CatBoost | 0,065 [0,017; 0,219] | 0,819 [0,748; 0,890] | 0,036 | 0,286 |

Тестовая выборка: 1 503 интервала, 14 положительных. Ансамбль по скважинам:

| Скважина | Интервалов | Положительных | PR-AUC | ROC-AUC |
|---|---|---|---|---|
| NO 15/9-F-11 | 773 | 8 | 0,058 | 0,879 |
| NO 15/9-F-14 | 363 | 4 | 0,038 | 0,831 |
| NO 15/9-F-5 | 367 | 2 | 0,072 | 0,948 |

**Интерпретация:**
- На скважинах, которых модель никогда не видела, ансамбль ранжирует интервалы по риску поглощения с ROC-AUC 0,88 против 0,67 у эвристики 2019 года; доверительные интервалы не пересекаются. PR-AUC ансамбля примерно в пять раз выше случайного уровня и вдвое выше эвристики, но при 14 положительных интервалах доверительные интервалы PR-AUC пересекаются.
- Ранжирование устойчиво во всех трёх тестовых скважинах (ROC-AUC 0,83–0,95), так что результат не держится на одной удачной скважине.
- Одиночные модели, кроме бейзлайна, приведены только для контекста. Более высокий PR-AUC LightGBM на тесте лежит в пределах шума (его доверительный интервал целиком перекрывает интервал ансамбля), и итоговая модель после просмотра результатов теста не менялась.
- ROC-AUC на тесте выше, чем на кросс-валидации (0,88 против 0,75), вероятнее всего потому, что все три тестовые скважины — эксплуатационные (F), похожие на большинство обучающих, а в кросс-валидации участвовала стабильно трудная скважина.
- **Это доказательство работоспособности подхода, а не готовый инструмент:** при пороге из кросс-валидации примерно одна тревога из двадцати приходится на настоящий интервал поглощения, и ловится около трети таких интервалов. Сигнал в данных реален, и модель его находит, но точность в рабочей точке пока далека от того уровня, которому доверял бы буровик, — это и мотивирует добавление стратиграфии и данных ГИС на следующем шаге.

## План работ

1. **Стратиграфия:** в суточных рапортах прямо названы свиты, склонные к поглощениям (Ty, Grid, Balder), поэтому свита интервала ожидаемо станет самым сильным недостающим признаком и заберёт на себя часть важности вертикальной глубины.
2. Подбор гиперпараметров бустингов (вложенный, без использования валидационных фолдов).
3. Признаки по ГИС (гамма-каротаж, плотностной и нейтронный каротаж) из полного датасета Volve, по соседним скважинам, чтобы избежать утечки.
4. Проверка событий со слабыми совпадениями с помощью LLM с валидацией на вручную размеченной выборке.
5. Модели для прихватов и осыпей.
6. Применимость к современным данным: рапорты Volve записаны в WITSML 1.4.1, а современные системы всё чаще используют WITSML 2.x / ETP, и каждый оператор заполняет рапорты по-своему, поэтому для промышленного применения понадобятся адаптер входных данных и проверка на данных в актуальном формате.
7. Демонстрационное приложение на Streamlit.

## Запуск

Нужен Python 3.12+ (проект разрабатывался на 3.13).

```bash
python -m venv .venv                 # создание виртуального окружения
source .venv/bin/activate            # в Windows: .venv\Scripts\activate
pip install -r requirements.txt
python -m scripts.download_data      # загрузка суточных рапортов Volve
python main.py                       # полный обучающий пайплайн
python -m scripts.diagnose_labels    # диагностика утечки
```

Тип осложнения, все пороги, правила разметки и параметры моделей задаются в `config/config.yaml`.
